# Project rules

- Use plain HTML, CSS, and JavaScript for the first prototype.
- Write readable code with descriptive English names and small functions.
- Keep HTML, CSS, JavaScript, and game content separate.
- Avoid unnecessary dependencies, abstractions, and excessive file splitting.
- Explain non-obvious decisions with short comments.
- Build in small milestones. Implement only the requested milestone.
- Verify gameplay facts and item effects; clearly flag anything unverified.
- Keep DLC and mod requirements separate.
- This is a personal gaming wiki with public source code and a locally hosted website.
- After each small, completed, validated improvement, create a descriptive commit and push it to this project's existing origin.
- Review the diff and stage only relevant files.
- Never commit secrets, private data, or unrelated changes.
- Never force-push.
- If Git or network permissions block an operation, report the exact blocker.
- Website deployment remains out of scope.
- After each milestone, explain the changed files, validation performed, and how the code works.
